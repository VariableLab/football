# 前后端一致性加固（2026-05-17）

## 背景

前后端之间没有共享类型合约，前端 ~50 个字段访问中有字段名对不上时会静默变 `undefined`。

## 改动清单

### 1. `backend/schemas.py` — 新增 5 个 Pydantic 模型

| Schema | 用途 |
|---|---|
| `MatchListResponse` | `GET /api/matches` 响应约束 |
| `StrategyResponse`  | `GET /api/matches/{id}/strategy` 响应约束 |
| `FeedbackOut` | 反馈条目模型 |
| `FeedbackListResponse` | `GET /api/feedback` 响应约束 |
| `ListResponse` | 通用分页包装器（可复用） |

同时修复 `PredictionOut`：
- 新增 `input_checksum: Optional[str]`（前端在竞彩弹窗和策略页都使用）
- `locked_at` 从必填改为 `Optional[datetime]`（匹配数据库可为空）

### 2. `backend/main.py` — 3 个端点加合约

| 端点 | 改动 |
|---|---|
| `GET /api/matches` | `response_model=MatchListResponse` |
| `GET /api/matches/{id}/strategy` | `response_model=StrategyResponse`，补齐 dict：`id`、`match_id`、`model_version`、`input_checksum`、`locked_at` |
| `GET /api/feedback` | `response_model=FeedbackListResponse` |

### 3. `static/openapi.json` — OpenAPI 规范

从后端自动生成的完整 OpenAPI 3.0 规范，覆盖全部 72 个端点。

### 4. `static/api/schema.ts` — TypeScript 类型

通过 `openapi-typescript` 从 OpenAPI 自动生成。包含所有端点的请求参数和响应体类型。

```ts
// 自动生成，开发时可直接 import
import type { paths, components } from './schema'
type MatchResponse = components['schemas']['MatchListResponse']
```

### 5. `tests/test_api_frontend_consistency.py` — E2E 测试

8 个测试，验证前端实际访问的每个字段都在 API 响应中存在：

- **4 个离线测试** — 检查 Pydantic Schema 字段完整性（运行无需后端）
- **4 个 Live 测试** — 启动后端后验证实际 HTTP 响应结构

运行方式：

```bash
# 离线
SECRET_KEY=your-key pytest tests/test_api_frontend_consistency.py -k "not live"
# Live
pytest tests/test_api_frontend_consistency.py -k "live"
```
